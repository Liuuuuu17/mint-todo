# Mint Todo desktop widget trial

This package contains an isolated macOS 14+ trial app and an actual WidgetKit extension. It is distributed as a separate pre-release and does not replace the production Mint Todo release or its update feed.

The 0.1.1 pre-release (app version 2.5.1, build 15) uses a leaf menu bar icon; the production app uses a checkmark. Both are template images that adapt to the menu bar appearance.

## Build and test

```sh
zsh build-widgets-trial.sh
zsh test-widgets-trial.sh
zsh test.sh
```

The trial build writes `MintTodo-Widgets-Trial.dmg`, `MintTodo-Widgets-Trial.zip` and a build log to `outputs/MintTodo-widgets-trial/`. `MINT_WIDGET_TRIAL_OUTPUT` overrides the output folder. The Xcode project is generated by `generate-project.py` and also opens normally in Xcode. Xcode generates App Intents metadata for both targets and signs the nested extension.

The default trial is built for the current Mac architecture. Set `MINT_WIDGET_TRIAL_ARCHS='arm64 x86_64'` to build a universal trial. A stable installation in `~/Applications` or `/Applications` lets the widget gallery discover the containing app.

## Features

- Small shows aggregate active-goal progress, completed/total task counts and today's outstanding count. It falls back to today's progress when no goal tasks exist.
- Medium displays up to three pending tasks from all dates, including future-dated, undated and overdue tasks, and links to the app's full pending list. Completed and cancelled tasks are excluded; the footer separately counts today's completions.
- Large shows two active goals with their progress, current phase and next task. A link opens the full planning window for other goals. Cancelled/archived phases and tasks are excluded from progress.
- The widget uses the app's background/paper choice, goal colours, rounded internal cards and selected font. Widget font scaling is bounded so text remains legible at system sizes.
- A three-size preview window uses the same views and the same completion command pipeline as the extension. Changes from the host app publish a new atomic snapshot and request WidgetKit timeline reloads.

## Signing and interaction modes

On this Mac, no Apple code-signing identity is installed. Native rendering succeeds with an ad hoc signature. System logs show that the App Intents service rejects the missing developer Team ID, so background `Button(intent:)` interaction cannot be validated with this identity.

The default `MINT_WIDGET_LOCAL_ACTIONS` mode therefore uses validated app links for completion. Clicking a widget circle wakes the trial app, records the requested state, applies it to the actual daily/goal stores, and reloads the widget. This mode requires no developer certificate. In the system WidgetKit Simulator, turn on Settings → Allow Links before testing these links.

The `CompleteMintTaskIntent` implementation remains available. After configuring an Apple Development/Developer ID identity and the appropriate Xcode signing settings, `MINT_WIDGET_USE_APP_INTENTS=1` builds the background-interaction variant. `MINT_WIDGET_SIGN_IDENTITY` passes the identity to Xcode. This variant still needs live validation under that identity before release. Do not invent a Team ID or disable system signature checks.

## Isolated data and durable sync

Bundle identifiers are `com.codex.minttodo.widgettrial` and `com.codex.minttodo.widgettrial.widgets`. The app stores tasks, goals, fonts and widget data under `~/Library/Application Support/MintTodoWidgetTrial/`; preferences use the trial bundle's domain. It seeds demonstration data only on first empty launch. System Reminders access and automatic software updates are disabled in this build.

The widget reads `widget-snapshot.json`. It never edits `tasks.json` or `goals.json`. Completion commands are immutable, uniquely named files in `WidgetActions/`, with an absolute desired state and subsecond timestamps. The host applies them serially, persists app state, publishes the snapshot, and only then acknowledges commands. Replays are idempotent; failed app/snapshot writes retain commands for retry. Pending commands can be overlaid on snapshots while the host is closed.

Without an App Group signing identity, the local trial extension is sandboxed with narrowly scoped macOS temporary file entitlements: read-only access to its snapshot and Fonts directory, and read/write access to WidgetActions only. It has no access to the production `OrbTodo` data directory and no network entitlement. A distributed production build should move the snapshot/journal to a provisioned App Group and migrate data explicitly.

## Verification

`test-widgets-trial.sh` compiles the actual stores, bridge, shared widget model/views and action types into an isolated test executable. It checks local-day filtering, linked and unlinked goal completion, main-app-to-widget updates, restart/replay, concurrent command writes, URL validation, rapid interaction ordering, cancellation and disk-failure recovery. `test.sh` covers the existing production app without trial compilation flags.

Native WidgetKit rendering is checked separately in Apple's WidgetKit Simulator. The preview window alone is not evidence of native extension execution. Test desktop placement and interaction on the target Mac before considering a public release.

Local live QA verified all three system widget sizes, a widget-link completion persisted in the actual trial task store, a system URL cold launch completed a goal task, and restoring daily items in the trial app appeared in the native widget after reloading. The final package also passed signature verification after extraction. The current trial passed 65 checks (including natural-time input and all-date pending-task filtering). Desktop placement has not been automated; this pre-release still requires cross-machine testing.

### Trial 日期与时间输入

新增任务时可识别“周三团建”“明天下午两点半到四点半培训”等中文日期和时间，创建前可修改日期、开始/结束时间或关闭时间设置。新增时将时间从标题中提取，如“明天下午2:30到4:30培训”整理为“培训”，可点“还原标题”撤回；编辑已有任务时点击“提取时间并整理标题”才会应用识别结果。仅日期的任务显示具体日期，时间段显示起止时间。识别在本机完成，无需 AI 服务。重复任务沿用时间段长度。

设置页按便签外观、苹果提醒事项、AI 设置与提示词、字体、窗口大小与工具排列；便签外观可切换直角与圆角。
